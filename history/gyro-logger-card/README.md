# The gyro logger card — superseded

> **Superseded by the blob card in [`../../gyro/`](../../gyro/).** Kept as
> history. Nothing in the tree builds it any more, and the sources here no
> longer assemble against their old neighbours.
>
> **已被 [`../../gyro/`](../../gyro/) 的 blob 卡取代**,保留作為歷史。
> 樹裡沒有任何東西還會建置它,這裡的原始碼也不再能跟舊的鄰居一起組譯。

## What it was / 它是什麼

The whole gyro logger as **one payload resident in the firmware RAM gap** at
`0xC072E064` — `logger.S`, four kilobytes of hook, ring, writer and post-process
handoff, with the lens profile generated by a second image (`PGEN.BIN`) fetched
from the card at boot. Built by `build_card.py`, installed by `makecard.py`,
released by `release_zip.py` as three files.

整個陀螺記錄器是**一整塊常駐在韌體 RAM 空隙的 payload**,位於 `0xC072E064` ——
`logger.S`,四千位元組的 hook、環形緩衝、writer 和後處理交接;鏡頭 profile 由
第二個映像(`PGEN.BIN`)產生,開機時從卡片讀入。

| | logger card | blob card |
|---|---|---|
| where the code runs | the cave, `0xC072E064`, 4,032 B | the pool, 14 KB |
| what the cave holds | all of it | four 8-byte veneers, allocated at boot |
| the lens profile | `PGEN.BIN`, a separate image | `gcsv_json.S`, in the blob |
| files on the card | AutoRun + fpSup.BIN + **PGEN.BIN** | AutoRun + fpSup.BIN |
| built by | `build_card.py` | `build_base_card.py` |
| shipped as | up to **v1.11b** | **v1.12.0** onwards |

## Why it was retired / 為什麼退役

**It ran out of room, and the room was the wrong shape.** The gap between the
firmware's own data and the park stub is 3,920 bytes. `logger.S` assembles to
4,032 and needs `0xC072E064..0xC072F024`, which is 112 bytes past the park stub;
`build_card.py` has refused to build it since 2026-09-03. Every feature after
that — the portrait patch, the phase probe, the frame anchor — had to be fitted
into whatever the logger had not taken, by hand, and the orientation stub was
lost twice that way.

The deeper problem is that a cave address written into a build is held whether
the card runs or not, so products had to be arranged around each other. The blob
card puts the code where there is room for it and asks for the few bytes the
firmware has to branch to. `../../explainers/fpsup-load-chain.html` is the
result.

**它塞不下了,而且那個空間形狀不對。** 韌體資料與 park stub 之間只有 3,920 bytes,
`logger.S` 組譯出來 4,032,要到 `0xC072F024`,超過 park stub 112 bytes ——
`build_card.py` 從 2026-09-03 起就拒絕建置。之後每一個功能都得塞進 logger 沒佔走的
縫隙,直拿的 stub 就這樣掉過兩次。更根本的是:寫進 build 的空洞區位址,不管那張卡
跑不跑都佔著。

## What is here / 這裡有什麼

| | |
|---|---|
| `build_card.py` `makecard.py` `release_zip.py` `build_pgen.py` | the builders and the installer |
| `logger.S` and its four variants | the payload: GYR, gcsv stream, backpressure probe, frame anchor, phase probe |
| `profilegen.S` `gcsvgen.S` `pgenload.S` and three `.inc.S` | the `PGEN.BIN` sidecar generator |
| `orient_stub.S` `orient_patch.S` | the portrait call-through, before `mode_hook.S` did it |
| `phase_probe.S` `phase_fwrite_patch.S` | the write-phase trace |
| `tableload.S` | had no caller left when it moved |
| `putprofile.py` `putpgen_stream.py` | pushed PGEN over USB during development |
| `test_logger_card.py` | 25 tests that came out of the live suite with them |

`test_logger_card.py` runs here. Twenty-two of its twenty-five pass; the three that
fail are the layout checks, and the number they fail by is the size of the
problem above. `profilegen.S` reaches back to `../../gyro/distfit.inc.S`, which
the blob still uses.

## Two things worth taking back / 有兩件事值得帶回去

These moved as logger tests but say something the blob generation has no test
for. Re-pointed rather than rewritten, they would be worth having:

- `test_the_autorun_arms_the_loader_only_after_writing_it` — the arming order is
  a property of any AutoRun, and `build_base_card.py` writes one too.
- `ProfilegenSource` — both camera-matrix focals have to come from the register
  the breathing term was folded into. `gcsv_json.S` emits the same matrix and
  nothing checks it.

## What its measurements are worth / 它量到的東西

`logger.S`'s comments carry the numbers that decided its shape and still decide
the blob's: the 692 ms worst-case SD write during recording, why the GYR build
uses 16 KiB halves and the text build three 32 KiB slots, and what r23/r27/r28
measured about queue depth. Those are in `notes/SD_WRITE_LATENCY_MEASURED.md`
and in the comments here.

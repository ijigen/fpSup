## 1. 结论

- 丢帧照抄 `FUN_c037a590` 的 `raw error` 三步，参数都是任务 id / 任务物件上的现成栏位。[F]
- 任务 id 就是 H2 的 r1，也是 `job+0x10FC`；用 `FUN_c03753c0(FUN_c0374220(), id)` 取任务指针（id < 0x60）。[F]
- 提交就是补做 H2 本来要做的 `C037AF20(yuv, id, 1)`。H2 之后 HIGHCONT 看 r0：非 0 = 成功。扣住／丢掉时 `bx lr` 并还原 r0 = Yuv 物件即可。[F]
- 自己注入的 S2 ON 走 `F_DISP`，**不经过**挂钩点 D，所以"看到码 6 就提交"只会发生在实体全按。[F]（P2 已如此）
- 半按放弃（S1 OFF / 超时 S2 OFF）必须把环里的帧丢掉，否则 RAW／任务槽泄漏。

## 2. 丢帧三步 [F]

`C037A66C` 起（kind 9 且缓冲首字 `0xDEADBEEF`）：

```
cap  = FUN_c03a4620()                    @ 单例 0xC359BE2C，保护字 0xC359BE44
FUN_c03a46b8(cap, job->+0xFFC, 0)        @ 剩余 += 预扣 − 0
raw  = FUN_c0377348()                    @ StillCreateRaw 0xC35200E4，保护字 0xC35201D4
FUN_c0377730(raw, job->+0x10FC)          @ 放下并释放 RAW；任务不在则断言
db   = FUN_c0374220()                    @ 任务库 0xC351FF44，保护字 0xC35200D8
FUN_c0375030(db, job->+0x10FC)           @ 释放任务
```

`FUN_c03753c0(db, id)`：`id < 0x60` 时回 `*(db+4 + id*4)`，否则 0。
`FUN_c0377730` 在查找为 0 时 `FUN_c0011100` 断言 → 丢掉前必须先查到任务。
`C037AF20` 同样在任务为 0 时断言 → 提交前也要查。

这三个 getter 第一次会建构。HIGHCONT 能出帧时它们一定已经建好。[I]
仍先读保护字，没建好就**原样放行**（不扣住），避免在 RAW 线程里建构。

## 3. 挑帧（4 格、167 ms）

目标：按下时环里是约 −0.5…0 s 的 4 张，且最新一张离按下最多一帧。

- `INTERVAL_US = 167000`（0.5 s / 3 段）。
- `origin` = 当前"最新那一格"开格的时间。
- 环空 → 入环，`origin = now`。
- `now - origin < 167 ms` → **换掉最新格**（丢掉旧的那张，新张占同一格，`origin` 不变）。
- 否则 → 满则丢掉最旧格，再入环，`origin = now`。

18 fps 时大约每 3 帧换一次最新格、每 167 ms 开一格；4 格覆盖约 0.5 s，最新格永远是刚到的帧。

## 4. 与 P2 按键的衔接

| 事件 | P2 | P3 加的 |
|---|---|---|
| S1 ON 且 kind 9 | pre=1，注入 S2 | 清空环 |
| 帧且 pre | 计数、超时、放行 | 按 §3 入环或丢掉，**不**入 YUV |
| 帧且 !pre | 计数、放行 | 同 P2 |
| 实体 S2 ON 且 pre | 放行 | pre=0，按时间把环交给 `C037AF20` |
| S1 OFF 且 pre | 先 7 再 5 | 先丢掉整环 |
| 码 7 且 pre | 清 pre | 先丢掉整环 |
| 超时 | 投递 7 | 在帧钩子里先丢掉整环、清 pre，再投递 7 |

帧钩子（状态机线程）与按键钩子（KeyMon 线程）用 `P_LOCK`（`swp`；`ldrex`/`strex` 这套组译器不收）互斥，只护环。

提交在按键线程做：与"H4 在分发里提交"的设计一致。实体 S2 之后立刻放开时，不能等下一帧（那一帧可能不再来）。

写测试时抓到两个真 bug：
1. 保护字循环 `b 8b` 跳回了 `add r0, pc`，第二次把 PC 再加一次 → 读到未映射地址。已改成只循环 `ldr`。
2. 超时只丢掉环、当前这一帧既不入环也不丢 → RAW 泄漏。已在超时路径先 `drop_one` 当前帧。

# 第一幀錯列：接收端 x 起點對照（2026-11-04，上機）

假說：我們的 TIM x0 = 16，接收端每列先跳 1 個 12 px 字（`0x3010000C` 高半 = x0/12 = 1）；原廠 UHD／FHD 都是 0。壞幀第 0 列開頭是 12 px 一組重複 4 次。

做法：暫存區副本，`apply/ap.c` 放好 TIM 列後把 X0 16 → 4、X1 − 12（寬度不變，畫面左移 12 感光元件 px），其餘同 v0.7.29test。版本 0.7.30test，`build/`（189,060 B），設定取自卡上 v0.7.29test。僅供測試，原始碼樹沒改。模擬確認：開錄時 `0x3010000C = 0x1F8`（x0/12 = 0，和原廠一樣）。

結果：12v2（key 10，3024×2020，29.97）10 段 A001_176–185：**第 1 幀 dy = 1 有 9 段**（只有 t02 正常）。基準 9/10、8/10。

結論：接收端跳字不是原因。剩下的接收端差異：y 起點（我們 20／40，原廠 172／354）、前端 `0x300F0244…`（原廠 0xC0、我們 0）、`0x30100004` 低半、`0x30100020`，見 `../20261103-first-frame-mmio-diff/README.md` 最後一節。

結束後刪除卡上的 v0.7.30test 和 v0.7.29test（重新同步沒效果、又讓開錄晚 63 ms），回到 v0.7.28test：它的重新同步 hook 在實機上從不觸發，行為等同 v0.7.27 記錄版。

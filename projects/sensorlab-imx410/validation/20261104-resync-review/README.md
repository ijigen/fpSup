## 新增的定位資訊

1. **故障在已觀測的完成回呼之前就存在。** 16 段 trace、64 組 done/write 配對的 raster 與四處共 160 B 樣本相同。16 個首幀 DNG 相同區域與 first-done 相同。異常首幀 row0 尾 64 B 保留 arm 時寫下的每段標記，頭 32 B 卻已改變；應稱首列局部未覆寫，不能說整列沒有寫入，更不能說 sensor 輸出整列缺失已證實。
2. **TG 行欄位解碼需修正。** 原廠 Thumb-2 `C0125770` 取 `30100590[29:16]`；不能直接把整個 word 當行數，或因原始 word 很大就丟棄。原始指令在 `C012577E`／`C0125794` 連讀兩次、各取 mask，相同才回傳，與 trace 的單讀不同。`C01258B0` 等此值回繞，`C01265C0` 用它避開 VMAX 尾端，支持 TG 行相位用途，不代表 sensor 線路封包編號。v28 異常首幀 9 段均為 2120，正常 t10 為 2121；v27 水平 2×1 異常為 4161，正常為 4162。後續正常幀也有例外值；單讀、回呼延遲及採樣時點均需考慮，這只是首幀計數／起動相位的線索。
3. **不要把下一個 DMA 位址當成錯用 buffer。** done 的 `30182280` 與當次 callback raster 不同，但 48/48 個可比的相鄰記錄都對應下一次 done 的 raster。callback 的參數與 writer raster 則 64/64 對應。
4. **resync 與 arm 相隔很久。** v29 t01 的 `CA=1` 為 48,129,358 µs，arm 為 48,889,748 µs，差 760.390 ms。故這次沒有驗證「貼近 DMA arm 的同步」。同一 timer 來源的 `0011→arm` 觀測，也取代舊路徑估算 137～168 ms。

## 限制及下一步

- 以上是 160 B 抽樣和 DNG 位移判斷，沒有全幀 completion 雜湊或原始 SLVS 封包。只將同區域的後段交接優先度降低，不全面排除所有後段錯誤。
- trace 本身含 64 B sentinel 和 arm 前 cache clean，會改變內容與時序；不能稱完全無介入。
- v27 t02 的 trace tag 寫成 `12v2`，實際設定為 key12／12h2，分類須以當次 bus／配方為準。
- 12v2 的設定標稱 RES 3024×2020，實際 trace／DNG raster 為 **3024×2014**；不可把標稱值當量測尺寸。
- 原廠格式、14-bit、高幀率、影音同步與 `0000` bit2 的持續影響沒有因此驗證。
- 下一個問題是「首列如何被局部寫入並計入一列」：先查接收窗、12-pixel 起點分組與 BUFA 首次啟動計數。既有離線 [MMIO 差異](../20261103-first-frame-mmio-diff/README.md) 只提出候選，尚未單獨驗證；不直接增加 reset／flush 猜測寫入。

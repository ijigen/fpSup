# RWZM 原廠 setter 與有限參數矩陣（離線）

`setter_proof.py` 執行 V5.02 的真 Thumb 指令，`report.json` 保存結果與韌體雜湊。
MMIO 只是模擬 RAM：已驗的是地址、參數映射、覆寫順序與這組設定的回填；沒有模擬影像、
沒有碰相機／USB，也沒有驗像素精度或實機復原時序。

## 已證實

- `c0101c30`（`out/decomp/full/blk_c01.c:1291`）200-byte 完整結構：
  +4/+8 → `300F0900` bit16/24，保留其它位元；+20 → 0910；+24/+28/+2C/+30
  四個 word 打包成 0914 的四個 byte；+34 → 0918；+40..+80 與 +84..+C4 為各17個係數。
  它不寫 enable bit0、H/V ratio 或 phase。
- `c0117d30`（同檔11106行）只複製 `c2f1226c` 的200-byte原廠表再呼叫完整setter。
  該地址必須從 **seg1_c2ef6e00.bin** 載入；直接讀 MAIN 的同一偏移會拿到別的原始資料。
  原廠值 flags=1/1、0910=16、0914=0x08100810、0918=0。副路徑表 c2f12334 完全相同。
- H/V 兩表每點精確等於 `floor(1024*(1−3t²+2t³)+0.5)`，`t=i/16`、i=0..16。
  首／中／末點1024／512／0。這支持「空間內插曲線」的解讀；**不證明 flags 控制曲線，
  不證明某一 flag 是位寬，也不表示這17點是17個空間 tap**。
- 常用 `c032d9a0 → c0635de0 → c0633e60`（blk_c03.c:29779、blk_c06.c:46739、45976）
  把0900整字寫1或0，因此清 bit16/24；H=2048或3072、V=1024時算出 H/V phase=0。
- `c0634038`（blk_c06.c:46071）則只更新0900 bit0，保留bit16/24；參數word4/5是H ratio/phase，
  word6/7是V ratio/phase。第二參數仍會寫 `300F0004` bit8，故不能忽略原值。
  原廠 `c017f990`（blk_c01.c:69084）實際使用phase512；它有兩軸設定，沒有RAW位深分支。
- 完整setter初始化還會由 `PictureQualityCommonCrct` 的 `c0697d20` 呼叫（blk_c06.c:123686），
  其條件是表變更／重建旗標，沒有12/14bit的直接分支。因此不能只看初始化值推定拍攝期間值。

## 不亂猜的第一輪矩陣

report.json 的8列：H ratio `{2048,3072}` × flags16/24 `{00,11}` × H phase `{0,512}`。
V固定ratio1024/phase0；0910/14/18與全部係數保持原廠值。
00與11兩組都來自已找到的原廠寫入；先不掃0910/14/18的未知值。
若flags有可重複效果，再單獨分離10與01，辨認是哪一軸／階段，不能直接當位寬開關。
phase是獨立的取樣問題：phase512可能帶來等權平均，但CFA相位、tap與邊界仍須像素證據。

原廠路徑順序應是正常幾何配置完畢後，從捕獲的typed結構更新flags，再用partial setter更新ratio/phase。
若之後又跑c0633e60，flags會被清掉，必須以實際捕獲時的readback判斷試驗是否有效。
操作必須在已有管線停止／鎖定流程內，不能向正在出幀的路徑零散改寄存器。
復原需要原來0004 bit8、0900 bit0/16/24、0908/090C、0910/14/18與係數；
原廠完整／partial setter能覆蓋這些欄位。腳本已驗本矩陣前後整個模擬MMIO範圍相同，
但沒有交付實機執行器或證明管線安全停止。下一次模式初始化也可能覆寫這些設定。

## 輸入來源與證據門檻

目前現成 RWZM 擷取是 **sensor → CRCT → RWZM → BUFA1**：`host/bufa1.py:1` 明確只讀現有buffer，
ISPL錄影／預覽擷取也沒有實作memory→CRCT/RWZM的已知圖樣注入。
HSEP/HSP3的memory圖樣走 `c01aa030 → SIG PRE`，不能宣稱它會經過RWZM。
所以這8列目前只能是sensor來源的候選篩選，尚不是受控bit-perturbation試驗。
任一候選出現非零low2，都可能是先降為12bit後由內插重新產生低位，不能據此宣稱真14bit。
完整證明需要已知RAW14輸入的低2bit擾動能按同色H2/H3算式影響輸出，並核對增益、偏移、飽和及邊界。

感光元件pattern是較可重複的候選來源，但現有 `captures/testpattern/p1..3`、`testpattern2/p1..3`、
`override_check` 七份BAYER metadata全是 **12-bit**；沒有找到RAW14 pattern fixture。
`IMX410_RULES.md:121`的斜坡6,6,6,7…／840 distinct驗的是12-bit解包，沒有證明1DN14步階。
真原廠入口 `XC_ImageSensorIMX410::v17 = c0324f70`（blk_c03.c:25291）只把command0/1/2/3
映為sensor02B2的0/1/5/5，沒有步階或位深參數（舊筆記c0324fd0是尾部位置）。
若後續使用pattern，必須先在RAW14的前級tap驗證其低位與重複性，再對照縮放；02B2不在161-register
mode blob內，復原必須明確關閉，不能依賴換模式。

## 格式不能代替精度

`c0630bf0`（blk_c06.c:43893）初始化BUFA1為12-bit；後續 `c0630e90`（44057行）確實可設
enum1 RAW14、enum2 u16。它只改3018220C的packing及30182214/18/1C的row geometry，
不改0900/0910/14/18；既有14-bit E3輸出仍為4倍數，所以只加大最後容器沒有證據可恢復低位。
本輪未找到原廠依RAW14/12切換上述RWZM未知欄位的分支；沒有找到確定可用的14-bit開關，
也不能用這個未找到的結果證明晶片所有設定都做不到。

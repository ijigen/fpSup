# H1 實機：水平 ÷3 成功，已測設定仍只輸出 12-bit 內容

2026-10-30，使用者授權「測看看」。本輪完成5個階段、每階段2幀，共10幀。
**成功取得第一級Hbin的有效全視野縮寬影像；真14-bit輸出目標未通過。**

## 結果

| 階段 | H1操作／抽頭 | 幾何 | 影像最低兩位 | 結果 |
|---|---|---|---|---|
| S0 | Crmf，mux1 | 6064×512 | mod4各約25% | 前置14-bit對照 |
| S1 | H1不合併，mux3 | 6064×512 | 全幀皆0 | 已測H1抽頭路徑為12-bit格點 |
| S2 | H1÷3，原廠核0，mux3 | 2016×512 | 全幀皆0 | 真縮寬，但仍為12-bit格點 |
| S3 | H1÷3，原廠核1，mux3 | 2016×512 | 全幀皆0 | 第二筆原廠核仍同樣丟低兩位 |
| S4 | Crmf，mux1 | 6064×512 | mod4各約25% | 後置14-bit對照 |

每格都有兩張非相同幀，像素與原始hash保存於 [report.json](report.json)。
H1控制0／1／0x10001、每幀水平源0／1、垂直源0、H2關閉、四組H1核與mux均已讀回核對。
兩筆核的前三個係數分別為16/32/16與4/56/4；這裡沒有用受控圖樣驗證完整tap方程式。

原始影像經目視確認是同一場景的動態取景，寬縮為約1/3，高度維持512：
[Crmf對照](run1/S0_crmf/view.png)、[H1÷3](run1/S2_h1_div3_kernel0/view.png)。
不是把全寬圖裁成中間1/3。此處未做精確取樣相位／權重校準。

實際DMA尾端也與幾何相符：全寬5,433,344 bytes，縮寬1,806,336 bytes。
每次抓圖前都填入sentinel，取得completion後回讀完整全寬範圍，再檢查實際改寫extent。
十幀均吻合預期，額外guard完整。這排除了「只把pitch欄改窄，實際仍寫全寬」的誤判。

## 本輪補上了什麼

舊T-C的H1控制被原廠每幀改回0，因此沒有有效H1影像。
本輪暫存並更新 `C31DF600/604` 原生每幀來源，加上 `C017FAA0` 的原廠控制，H1設定得以保住。
先前的「H1精度未知」已有新的有效樣本：**本輪測到的a0 H1輸出設定丟低兩位**。
前後Crmf仍保有14-bit低位內容，不能把結果歸因於整個sensor來源或RAW14解碼都已變12-bit。

這是獨立a0擷取同一H1抽頭；沒有部署完整原生BufA7→SIG錄影工作。
沒有受控RAW14 bit-perturbation輸入、全幅吞吐、錄影並行或所有未知參數的覆蓋。
結論限於已測配置，不宣稱H1電路的固定內部位寬，也不擴大成所有未知路由不可能。

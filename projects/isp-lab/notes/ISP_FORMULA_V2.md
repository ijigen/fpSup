# ISP custom 公式 v2：從零設計（草案 2026-10-27，待使用者確認）

使用者 10-27：「從零開始設計新的統一公式，不寄託 mode」。
v1（`open-gate/build/imx410_profile.py`）是「原廠 78 列 + 一路補例外」長出來的：預覽倍率從原廠候選清單挑、
M12／M98／M102 各有自己的測試在撐規則。v2 只從**量到的硬體規則**推導，原廠列只當回歸檢查，不當設計輸入。

## 1. 輸入（全部由產品 UI 或 IMX410 custom 給，沒有 mode 名稱）

| 名稱 | 意思 | 來源 |
|---|---|---|
| `W, H` | 感光元件送進 ISP 的光柵（讀出窗） | IMX410 custom（任何讀出，原廠或虛擬） |
| `sx, sy` | 一個光柵像素涵蓋幾個感光元件像素（感光元件合併） | 同上 |
| `Rw` | 要的錄影寬（可見寬 + 16），或直接給倍率 `Z` | 產品 RES |
| `vbin` | 1 或 3（品質：CRCT 垂直平均） | 產品品質選項 |
| `bits` | 8／10／12／14 | 產品 FMT |
| `fps` | 決定 `hirate`（>60） | 產品 FPS |

## 2. 硬體規則（全部有實機證據，ISP_CAPABILITY_MAP §0.5）

- **R1 RWZM**：每軸 1024–8191；8192 起壞（13 位元）。1023 = 1:1 直通。只縮不放。
- **R2 錄影兩軸都 1:1 時 bin 不作用**：兩軸 RWZM 1:1 加 bin → 只拿到左上角裁切（分支 B／D）。**只要一軸非 1:1 就行**（10-27 bin3：b1x3-z3072x1024、b3x1-z1024x3072 通過）；兩軸都要 1:1 時改用 RWZM **1025**（bin4：b3x3-z1025、b3x1-z1025 通過），少掉的 ≤16 px 由感光元件裁切多 16 px（6064）補回。
- **R3 水平 CRCT bin 要 binfilt**：分支 C 的 Hbin2 已經水平 ÷3，主管線 +0x24 的 ÷3 是第二次 → 畫面被擠進左 1/3。res-custom `ogc_binpath` 把它清成 1；isp_custom 裝 `host/asm/binfilt.S`（同一套：選擇器 0xC0325228 之後修、兩個核寫入點 0xC032DDE8／DE68）。10-27 bin2：有 hook 通過（命中 2／10）、無 hook 對照 fov 0.679 失敗。核（kh／kv 0–5、soft/std）有作用：kh5（不濾）時間雜訊 1.78 對 kh1 1.18。
- **R4 垂直 CRCT bin（×3）可用且真的平均**，只在分支 C（預覽每軸等於錄影）成立；雜訊 ×0.61。
- **R5 永不分支 F**：預覽和錄影都縮放而不相等 → 錄影中 LV 變放大局部；預覽有 ÷3 時連錄影也被 ÷3。
- **R6 預覽來源**：預覽來源寬 ≤ 2100、可見寬 ≤ 2000（16 的倍數）、光柵 = 可見 + 16/10 且不超出來源。
- **R7 平面碼**：`+0x80/+0x84` = {8:(10,10), 10:(10,9), 12:(7,7), 14:(7,8)}；任何路線都可換。
- **R9 C 不設倍率上限**（10-27 mx1／cmax）：E1 在 act×Z > 2000 時截掉錄影中 LV（M74 0.945）；C 在 Z 3119／3218（無 bin）、6436（vbin）實測正常。
- **R10 錄影 1:1 的預覽整數倍率要同時滿足「來源 ≤ 2100」與「可見 ≥ act」**（10-27 sby M60／M55：S35 2096／4192 只顯示 0.95）。
- **R8 錄影尺寸**：`rec = (W / vbin_h… ) × 1024 / Z`，寬 &~15、高 &~1；`act = rec − (16, 10)`。

## 3. 推導（一條路，沒有候選清單）

1. **錄影倍率**：`Zh = ceil(W·1024 / Rw)`、`Zv` 同理（或直接給）；夾到 R1。`vbin = 3` 時 `Zv' = Zv / 3`（總倍率不變）。
   不符 R1 → 這個組合不存在（UI 不列出），不是 clamp。
2. **路徑**（決定預覽）：
   - `vbin = 3` → **C**：預覽 = 錄影（bin 與 RWZM 每軸相等）；R6 不成立 → 組合不存在。
   - 否則，錄影是 1:1 → **B**（預覽 = 1:1，若 `W ≤ 2100`）或 **D**（預覽縮到 ≤2100 的最小 RWZM）。
   - 否則錄影縮放：等向且 `W·1024/Z ≤ 2100` → **C**；`W ≤ 2100` → **E1**（預覽 1:1）；`W ≤ 6300` → **E3**（預覽 ÷3＋1:1）。
   - 其他 → 組合不存在。
3. **預覽欄位**：可見 = act 換到預覽像素，依 R6 夾；光柵 = 可見 + 16/10。
4. **待機欄位**（6 個待機 profile 的 +0x20/+0x28）：= 錄影視野換到待機視窗（2016×1344 = 全片幅 ÷3）。
   **裁切讀出也寫**（10-27 sby 實測：APS-C、S16、正方形、S35 待機都正確跟著裁切；讀出置中，所以較小的待機可見區就是裁切區，
   與 Jose 的 S16 待機框同法）。⚠ 待機 profile 只在 LV 重建時生效（半按／放大／選單切格式）→ 產品端套用格式後必須觸發 LV 重建。
5. **其他欄位**：R7、`hirate`、影片類常數（+0x1C=1、+0x88=0、+0x90=1、+0xC0=0、+0x38 = 預覽 ÷3 時 16 否則 1）。

## 4. 驗證方式（不變）

每個組合 = Want → 公式 → 整列 → RAM 安裝 → 丟棄錄影 → 五檢查點；判定：尺寸、位深、待機視野（雙向配準 ±3%）、
錄影中 LV 視野（0.95–1.02）。原廠 78 列只做回歸：v2 對原廠輸入必須算回原廠列（不一致就是 v2 或規則錯）。
